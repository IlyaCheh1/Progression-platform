# Рекомендуемые настройки Cursor

## Обязательное

1. **Plan Mode для сложных задач**
   - Используйте для функций, затрагивающих несколько модулей, архитектуру, данные или инфраструктуру.
   - Сохраняйте важные планы в workspace и коммитьте вместе с кодом при необходимости.

2. **Иерархический `.cursorignore`**
   - Включите поиск ignore-файлов в родительских каталогах, особенно в монорепозиториях.
   - Секреты исключайте через `.cursorignore`, большие сгенерированные файлы — через `.cursorindexingignore`.

3. **MCP approvals**
   - Оставьте подтверждение действий включённым.
   - Авторазрешение допустимо только для явно безопасных read-only инструментов.

4. **Минимальный MCP-набор**
   - Постоянно: Context7 и GitHub.
   - Playwright включайте на этапах UI/E2E.
   - Sentry, Figma и БД включайте только для соответствующей задачи.

5. **Subagents**
   - Начните с 2–3 специализированных агентов.
   - Архитектурный и security-review делайте read-only.
   - После реализации запускайте независимого verifier.

## Режим работы

- Рутинные правки: Agent напрямую.
- Новая крупная функция: Plan Mode → feature-planning → implement-from-plan → quality-gate → verifier.
- Баг: root-cause-debugging → минимальный fix → regression test → verifier.
- Параллельные крупные ветки: отдельные Git worktrees или Cloud Agents, а не несколько агентов в одной рабочей директории.

## Выбор модели

- Для исследования кодовой базы и простых правок используйте быструю модель/Auto.
- Для архитектуры, миграций, сложной отладки и security-review выбирайте модель с сильным reasoning.
- Не фиксируйте конкретное имя модели в общих правилах: доступность и лучшие модели меняются.

## Контекст

- Не вставляйте длинные style guide в одну глобальную rule.
- Делите правила по областям и ограничивайте их glob-паттернами.
- Ссылайтесь на канонические файлы проекта вместо копирования их содержимого.
- После повторяющейся ошибки агента добавляйте короткое конкретное правило.
