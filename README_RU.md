# Cursor Pro Kit для сложных сайтов и ПО

Готовый стартовый набор для крупных full-stack проектов, монорепозиториев и долгоживущих продуктов.

## Что внутри

- `.cursor/rules/` — постоянные правила архитектуры, TypeScript, frontend, backend, БД, тестов и безопасности.
- `.cursor/skills/` — повторяемые рабочие процессы: планирование, реализация, отладка, quality gate и подготовка релиза.
- `.cursor/agents/` — три специализированных субагента: архитектура, безопасность и независимая проверка.
- `.cursor/mcp.json.example` — минимальный MCP-набор: Context7, GitHub, Playwright.
- `.cursor/mcp.optional.json.example` — опциональные Sentry, Figma и Supabase в read-only режиме.
- `.cursorignore.example` и `.cursorindexingignore.example` — защита секретов и уменьшение шума индексации.
- `SETTINGS_RU.md` — рекомендуемые настройки Cursor.
- `PROMPTS_RU.md` — шаблоны запросов для сложных задач.

## Быстрый старт

1. Скопируйте содержимое набора в корень репозитория.
2. Переименуйте `.cursor/mcp.json.example` в `.cursor/mcp.json`.
3. Экспортируйте секреты в окружение, а не записывайте их в JSON:

```bash
export CONTEXT7_API_KEY="..."
```

4. Перезапустите Cursor и проверьте MCP в `Customize → MCP`.
5. Оставьте только те MCP, которые реально нужны текущему проекту.
6. В начале крупной задачи включайте Plan Mode, затем запускайте реализацию по утверждённому плану.

## Рекомендуемая стратегия

- **Rules** описывают постоянные ограничения проекта.
- **Skills** описывают повторяемый процесс выполнения задачи.
- **Subagents** нужны для независимой проверки и контекстно тяжёлых исследований.
- **MCP** подключайте только для внешних систем, к которым Cursor сам доступа не имеет.

Не устанавливайте отдельные Filesystem/Git MCP без необходимости: Cursor уже умеет читать и менять файлы, искать по кодовой базе и запускать терминал. Лишние MCP увеличивают количество доступных инструментов, контекст и поверхность атаки.

## Безопасность

- Используйте OAuth или токены с минимальными правами.
- Для БД по умолчанию включайте read-only и привязку к одному проекту.
- Не давайте агенту доступ к production-секретам, дампам и ключам.
- Не включайте автоматическое подтверждение мутирующих MCP-инструментов для production.
- Проверяйте diff, миграции и команды развертывания вручную.
- `.cursorignore` не является абсолютной песочницей: терминал и внешние MCP могут иметь собственный доступ к файловой системе.
