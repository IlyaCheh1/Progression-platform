# Шаблоны промптов

## Сложная функция

```text
Работай в Plan Mode. Изучи существующую архитектуру и найди канонические примеры.
Цель: <что нужно построить>.
Ограничения: <совместимость, безопасность, производительность>.
Критерии приёмки:
- <критерий 1>
- <критерий 2>
- <критерий 3>
Сначала подготовь план с затрагиваемыми файлами, контрактами, миграциями, тестами и рисками. Код не меняй до завершения плана.
```

## Реализация утверждённого плана

```text
Используй skill /implement-from-plan. Реализуй план небольшими проверяемыми шагами. После каждого логического этапа запускай релевантные проверки. Не меняй публичные контракты без явной причины. В конце запусти /quality-gate и verifier.
```

## Исправление бага

```text
Используй /root-cause-debugging. Сначала воспроизведи проблему и собери доказательства. Не исправляй симптомы. Добавь regression test, внеси минимальный fix и повторно запусти проверки. Отдельно укажи первопричину.
```

## Code review

```text
Проведи независимый review текущего diff. Ищи ошибки корректности, гонки, нарушения контрактов, проблемы безопасности, доступности, производительности и отсутствие тестов. Не пересказывай diff. Выдай замечания по severity с файлами и строками.
```

## UI из Figma

```text
Используй Figma MCP только для получения design context и ассетов. Сначала найди существующие компоненты и tokens в репозитории. Не создавай дубликаты компонентов. Реализуй responsive states, loading/error/empty states, keyboard navigation и accessibility. Проверь результат через Browser или Playwright.
```
